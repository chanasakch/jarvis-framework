## G1 BLOCKED: การแก้ไขไฟล์ที่เฟรมเวิร์กเป็นเจ้าของ

`guard.js` จะหยุดการเรียก `Write`, `Edit`, `MultiEdit` หรือ `NotebookEdit` ทุกครั้งที่ไฟล์ปลายทาง
ขึ้นต้นด้วย `.jarvis/state/`, `.jarvis/core/`, `.jarvis/scripts/` หรือ `.claude/` และแสดง
ข้อความนี้

```text
G1 BLOCKED: <file> is framework-owned and must not be edited during normal work.
Instead: These are framework-owned files. To change the framework, start Claude Code
with JARVIS_DEV=1, or open a PR against the jarvis-framework repo.
```

ถ้าไฟล์อยู่ใต้ `.jarvis/state/` ข้อความส่วน Instead จะเจาะจงกว่านี้ เพราะ state เป็นของ CLI
คนเดียว วิธีแก้คือใช้ `node .jarvis/scripts/jarvis.js set|task|flags ...` ห้ามแก้ไฟล์ตรง ๆ

<Callout kind="tip" title="JARVIS_DEV=1">
ถ้ากำลังพัฒนาตัว framework เอง เช่น แก้ agent, workflow YAML หรือ `guard.js` ให้เปิด
Claude Code โดยตั้ง environment variable `JARVIS_DEV=1` ไว้ G1 จะเช็กตัวแปรนี้ก่อนอย่างอื่น
ถ้าค่าเป็น `1` ก็ยอมให้เขียนไฟล์ได้ พอกลับมาทำงานโปรเจกต์ตามปกติให้ unset ค่านี้ด้วย
ไม่อย่างนั้น guard จะเลิกป้องกันไฟล์ของ framework ให้คนอื่นในทีมไปด้วย
</Callout>

## G2 BLOCKED: Claude พยายามรันคำสั่งที่คนต้องรันเอง

guard จะเช็ก `approve`, `force`, `skip`, `reopen`, `park` และ `unpark` กับทุกคำสั่ง `Bash`
ที่เรียก `jarvis.js <verb>` หรือ `npm run -s <prefix> -- <verb>` แล้วแสดงข้อความนี้

```text
G2 BLOCKED: "<verb>" is a human-only command (spec §8.2).
Instead: print the command and ask the user to run it, for example:
  ! npm run -s jarvis -- <verb> <ID> <phase> --reason "<why>"
```

ไม่ใช่บั๊กเรื่องสิทธิ์ ระบบตั้งใจให้เป็นแบบนี้ Claude จะพิมพ์คำสั่งที่ต้องรันออกมาให้ (ใส่แฟล็ก
`--reason` ให้ด้วยถ้าคำสั่งนั้นต้องใช้) แล้วหยุดรอให้คุณรันเอง เหตุผลที่การอนุมัติ, force, skip,
reopen และ park เป็นคำสั่งที่คนต้องรันเอง อ่านได้ที่ [Gate](/docs/gates)

## G3 BLOCKED: การแก้ไขซอร์สโค้ดนอก phase implement หรือ test

แก้ไฟล์ไหนใต้ `apps/` หรือ `packages/` ก็จะโดนบล็อก ยกเว้นมี work item ที่อยู่ใน phase
`implement` (แก้ได้ทุกไฟล์) หรือ phase `test` (แก้ได้เฉพาะไฟล์เทสต์ที่ตรงกับ
`_test.go`, `.test.tsx`, `.spec.ts`, `__tests__/`, `e2e/` หรือ `tests/`) ข้อความที่แสดงคือ

```text
G3 BLOCKED: <file> is source code, and no work item is in the implement phase
Active items: <ID>:<phase>, <ID>:<phase>
Instead: run the phase that owns this change:
  node .jarvis/scripts/jarvis.js next <ID>
  node .jarvis/scripts/jarvis.js set <ID> implement in_progress
Source edits happen inside implement (any file) or test (test files only).
```

ส่วนใหญ่เจอตอนที่ Claude จะ "แก้ให้เลย" ระหว่าง phase requirements, architecture หรือ
review แทนที่จะส่งงานไปทำใน phase implement ให้รันคำสั่งตามที่แสดง ถ้าทีมไม่อยากใช้
guard ตัวนี้ ปิดทั้งโปรเจกต์ได้ด้วย `gates.source_guard: false` ใน
`jarvis.config.yaml`

## G4 BLOCKED: การแก้ไข migration โดยไม่มีการประกาศ DB change

ไฟล์ใต้ path `migrations_mysql` หรือ `migrations_mongo` ที่ตั้งค่าไว้จะโดนบล็อกทั้งหมด ยกเว้นมี
work item ที่กำลังทำอยู่ตั้ง `flags.has_db_change === true` ไว้ ข้อความที่แสดงคือ

```text
G4 BLOCKED: <file> is a migration, but no active work item has has_db_change=true.
Instead: set the flag on the item that owns this change:
  node .jarvis/scripts/jarvis.js flags <ID> has_db_change=true
If this is not a DB change, the file does not belong in a migration folder.
```

ถ้าแฟล็กนี้ควรตั้งไว้ตั้งแต่ตอน intake ให้รันคำสั่ง `flags` ข้างบน แต่ถ้าไฟล์นี้ไม่ได้เป็น
migration ของ schema หรือข้อมูล ให้ย้ายออกจากโฟลเดอร์ migrations ไป

## G5 BLOCKED: การอ่านหรือเขียนไฟล์ secret

เครื่องมือทุกตัวที่แตะไฟล์ `.env` (ยกเว้น `.env.example`/`.env.sample`/`.env.template`),
`.pem`, `.key`, `id_rsa*`, `id_ed25519*`, `credentials.json/.yaml`, `secrets.*`, `.p12` หรือ
`.pfx` จะโดนบล็อก ทั้งเครื่องมือ `Write`/`Edit` และคำสั่ง shell (`cat`, `grep`, `cp`, `source`, …)
ที่จะอ่านหรือคัดลอกไฟล์พวกนี้ ข้อความที่แสดงคือ

```text
G5 BLOCKED: <file> is a secret file. Jarvis never reads or writes secrets.
Instead: read the variable NAMES from .env.example or the config schema, and describe
the value the user must set.
```

Jarvis ไม่ต้องรู้ค่าของ secret เลย รู้แค่ชื่อก็พอจะบอกได้ว่าคุณต้องตั้งค่าอะไร
ถ้าเจอข้อความนี้กับไฟล์ที่ไม่ใช่ secret (ชื่อไปตรงกับ pattern โดยบังเอิญ) ให้เปลี่ยนชื่อไฟล์
หรือขอให้ผู้ใช้ส่งมาเฉพาะบรรทัดที่เกี่ยวข้อง

## gate ไม่ผ่านซ้ำจนครบขีดจำกัดการ retry

ทุกครั้งที่ script gate หรือ gatekeeper ไม่ผ่าน ปัญหาจะถูกส่งกลับไปให้ agent ตัวเดิม
และนับจำนวนครั้งเพิ่มขึ้นหนึ่ง เมื่อครบ `gates.max_retries` (ค่าเริ่มต้น 3) orchestrator จะเลิก
retry แล้วแสดง Gate Failure Menu แทน

```text
⚠️  GATE FAILED: FEAT-012 / review (attempt 3/3)
Blocking issues:
  - [F-SEC-001][critical] Raw DB error returned in POST /v1/otp response
  - [F-PERF-002][major] Query inside loop in otp/service.go:88
Risk if forced: <one or two lines>
Options:
  1) Retry — send issues back to the agent (resets attempts)
  2) Fix manually, then run: /jarvis FEAT-012
  3) Force pass (human only, audited):
     ! npm run -s jarvis -- force FEAT-012 review --reason "<why>"
  4) Park work item:
     ! npm run -s jarvis -- park FEAT-012 --reason "<why>"
```

ระบบไม่ได้พัง แค่ไม่ยอมวนแก้ finding เดิมที่ยังแก้ไม่ได้ไปเรื่อย ๆ ให้เลือกหนึ่งในสี่ทาง
รายละเอียดของกลไก (finding ที่ force ผ่าน gate ไม่ได้, audit trail, chore ติดตามผลที่สร้างอัตโนมัติ)
อยู่ในหน้า [Gate](/docs/gates)

## การเช็กแบบ deterministic รายงานผลเป็น `skipped` แทนที่จะเป็น `pass` หรือ `fail`

`jarvis.js check backend|frontend` รันคำสั่งที่ตั้งไว้ใต้ `commands.backend` และ
`commands.frontend` ใน `jarvis.config.yaml` ก่อนรันแต่ละคำสั่งจะหาไดเรกทอรีที่คำสั่งนั้น
`cd` เข้าไป (หรือ workspace ที่ระบุด้วย `-w <dir>`) ถ้ายังไม่มีไดเรกทอรีนั้น ผลจะเป็น `skipped`
พร้อมเหตุผลอย่าง `apps/api does not exist` ไม่มีทางเป็น `fail` และถ้า output ของคำสั่ง
ดูเหมือนยังไม่ได้ติดตั้งเครื่องมือ คือมี `command not found` หรือ `ENOENT` อยู่ในบรรทัดเดียว
ผลก็จะเป็น `skipped` (ไม่ใช่ `fail`) เหมือนกัน

ดังนั้นถ้ายังไม่มี `apps/api` หรือ `apps/web` หรือยังไม่ได้ติดตั้งเครื่องมืออย่าง `golangci-lint`
การได้ `skipped` ถือเป็นเรื่องปกติ ไม่ได้แปลว่า pipeline พัง รัน
`node .jarvis/scripts/jarvis.js doctor` เพื่อดูว่าขาดเครื่องมือตัวไหน พร้อมคำแนะนำวิธีติดตั้ง
ของแต่ละตัว

## คำสั่งหรือ agent ดูเหมือนไม่อัปเดตหลังจาก upgrade

`npx github:chanasakch/jarvis-framework upgrade` แทนที่ไฟล์ของ framework (`.jarvis/core/`,
`.jarvis/scripts/`, `.claude/agents/`, `.claude/commands/`) บนดิสก์ก็จริง แต่ Claude Code โหลด
slash command และ agent definition ครั้งเดียวตอนเริ่ม session ถ้าอัปเกรดแล้วยังเห็นข้อความเก่า
ของ `/jarvis-help` หรือ agent ยังทำงานแบบเดิม ให้ restart Claude Code เพื่อให้อ่านไฟล์ใหม่
upgrade ไม่แตะ `.jarvis/standards/`, `jarvis.config.yaml`, `.jarvis/project/` และ `CLAUDE.md`
เลย restart ไปก็ไม่เสียไฟล์ของคุณ
